# v0.3.0 Implementation Plan: backport-aware verdicts, real image probes, reports, Action

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close every gap against adityaaravind/php2shell-check (real image/container probes, HTML/Markdown reports, a reusable GitHub Action) and add the one thing no PHP2Shell tool does: stop calling distro-backported builds vulnerable.

**Architecture:** Everything stays in the single file `php2shell_check.py`. Distro-package evidence is a new `PackageInfo` on `PhpInstall`, filled locally in Python and remotely by new lines in the existing POSIX `sh` probe. Docker image and container probes pipe that same `sh` probe into `docker run`/`docker exec`, so they get CLI+FPM, ini posture, backport evidence and the restart check from the same code that powers SSH mode. Reports render from one normalized row type.

**Tech Stack:** Python 3.9+ stdlib only (`gzip`, `html`, `shlex`), POSIX `sh`, `unittest`, GitHub Actions composite action.

**Spec:** No separate spec doc. The decisions are agreed in the session of 2026-10-30 and recorded in "Decisions" below; executors read that section as the spec.

## Decisions

1. **Backports.** A version-affected install is reported `patched_backport` only when the changelog of the package owning the binary names **both** `CVE-2026-109618` and `CVE-2026-109619`. Anything less leaves the version verdict alone and adds a note. Never downgrade on missing evidence. (Verified 2026-10-30: Red Hat *rebases* bump the version and do not name the CVEs, so the version check already handles them; *backports* such as RHEL `8.0.30-8.el9_8.1`, AlmaLinux `.alma.1`, Remi EOL builds keep the old version and the changelog names both CVEs. Debian bookworm/trixie fixed by moving to 8.2.35 / 8.4.27, DLA-4848-1 / DSA-6574-1.)
2. **Images and containers** are probed by running PHP inside them, with `--network none` for images. Dockerfile tag reading stays as it is.
3. **Reports:** `--markdown FILE` and `--html FILE` on `check` and `scan-docker`. The HTML is one self-contained file with no scripts, CDNs or web fonts.
4. **GitHub Action:** a composite `action.yml` at the repo root that writes the Markdown report to the job summary.
5. **Not built, on purpose:**
   - No URL / `X-Powered-By` mode. "No probe traffic" stays a trust point (SECURITY.md).
   - No `--define` what-if mode. `php -d k=v` always takes effect on the command line, so it proves nothing about whether the php.ini/FPM-pool rollout worked. Our `check` already reads the *effective* ini from `php -i` and `php-fpm -i` after rollout, which is the real test.

## Global Constraints

- Python **3.9+**, **zero runtime dependencies**, tool stays **one file** (`curl -O` install is a README promise).
- **No exploit traffic and no URL mode**; image probes run with `--network none`.
- Every string from a remote host, container, image or package changelog is untrusted. Pass it through `_clean()` before printing to a terminal, and `html.escape()` before putting it in HTML.
- Existing JSON keys, exit codes and `--fail-on` behaviour are unchanged. New keys are additive.
- User-facing text (README, CHANGELOG, help, report copy) has **no em dashes**.
- Commits are authored by the repo-configured user, with **no `Co-Authored-By` or AI trailers**.
- Tests go in `tests/test_check.py` (stdlib `unittest`, existing style: one `class XTests(unittest.TestCase)` per feature, mock `subprocess.run`, posix-only tests use `skipUnless`). Run with `python -m unittest discover tests` on Windows, and under WSL `Ubuntu-D` for posix tests (see memory `wsl-linux-verification`). Docker is not installed locally, so real Docker runs only in CI (Task 5).

## Review Focus

1. **Only one CVE in the changelog** (a partial backport, or a changelog that mentions just one ID): the verdict must stay affected, with a note naming the missing ID. Tested in Task 1.
2. **Package exists but the changelog is gone**: Docker-slim and minimal images strip `/usr/share/doc` with dpkg `path-exclude`, and Ubuntu sometimes symlinks `phpX.Y-cli` docs to `phpX.Y-common`. Try `<pkg>`, then `phpX.Y-common`. If neither exists, leave the verdict as is and add the note "package changelog not available". Tested in Tasks 1 and 2.
3. **Binary owned by no package**: built from source, which includes every official `php:` Docker image. No package line, no extra note, verdict unchanged. Tested in Tasks 1 and 3.
4. **Hostile strings in the HTML report**: an image name, remote binary path or changelog-derived detail containing `<script>` or `"`. It must be escaped. Tested in Task 4.
5. **Image or container without `sh`** (distroless) or with no PHP; an image ref starting with `-`; Docker CLI missing or the daemon down. Each must give an `UNKNOWN` row or a note with the reason, never a traceback. An option-like ref is rejected before Docker runs. Tested in Task 3.

It returns None if nothing is readable.
  - `apply_backport(ins: PhpInstall) -> None` mutates `ins.verdict` in place.
  - `backport_notes(ins: PhpInstall) -> list[str]`

- [ ] **Step 3: Extend the probe template** inside the per-binary loop, after the `INI` line. It uses only POSIX `sh`, `readlink -f`, `gzip -dc` and `grep -o`, and every command is guarded with `2>/dev/null`:

```sh
  real=$(readlink -f "$p" 2>/dev/null || echo "$p")
  if command -v dpkg >/dev/null 2>&1 && pkg=$(dpkg -S "$real" 2>/dev/null | head -n 1 | cut -d: -f1) && [ -n "$pkg" ]; then
    echo "PKG dpkg $pkg $(dpkg-query -W -f='${Version}' "$pkg" 2>/dev/null)"
    cl=""
    for d in "$pkg" "$(echo "$pkg" | sed 's/-[a-z]*$/-common/')"; do
      [ -r "@DOC@/$d/changelog.Debian.gz" ] && { cl="@DOC@/$d/changelog.Debian.gz"; break; }
    done
    if [ -n "$cl" ]; then gzip -dc "$cl" 2>/dev/null | grep -oE '@CVE_RE@' | sort -u | sed 's/^/CVE /'; else echo NOCHANGELOG; fi
  elif command -v rpm >/dev/null 2>&1 && pkg=$(rpm -qf --qf '%{NAME} %{VERSION}-%{RELEASE}' "$real" 2>/dev/null); then
    echo "PKG rpm $pkg"
    rpm -q --changelog "${pkg%% *}" 2>/dev/null | grep -oE '@CVE_RE@' | sort -u | sed 's/^/CVE /'
  fi
```

  `@CVE_RE@` is built from `CVES` as `"|".join(map(re.escape, CVES))`. `@DOC@` is `doc_root`. Python's `changelog_cves` and this regex both read from the single `CVES` list. `parse_remote_probe` handles `PKG` by splitting into manager, name and version, with `cves=[]`; it appends on `CVE`, sets `cves=None` on `NOCHANGELOG`, and calls `apply_backport` in `close()`.
